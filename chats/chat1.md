## 二、Token 必须先行（你的直觉是对的）

Token 不先定，组件就是流沙。我打算定这几组，全部用 CSS Variables，**同时支持暗亮和缩放**：

- **颜色** — 不只是"灰"，而是一套有温度的冷色阶。背景层 4 级（canvas / surface / raised / overlay），文字 4 级（primary / secondary / tertiary / disabled），描边 2 级（hairline / strong），强调色一支克制的（藏青或鸭蛋青系，不亮不跳），状态色 4 支（success/warn/danger/info）但都偏低饱和。**不用纯黑也不用纯白**——暗色是 `oklch(0.18 0.005 250)` 那一档的炭灰，亮色是 `oklch(0.98 0.003 90)` 那一档的米白。
- **字体** — 中英文双系统。英文我倾向 **Söhne / Inter Display / Geist**（取一），中文用**思源宋体 / 思源黑体 Variable** 或 **HarmonyOS Sans**。字号 8 级（11 / 12 / 13 / 14 / 16 / 20 / 28 / 40），行高、字重、letter-spacing 全部成对绑定，不允许单独调字号。
- **间距** — 4px 基线的 8 级 scale。
- **圆角** — 4 级（2 / 6 / 10 / 16），媒体卡用 10，弹窗用 16，按钮用 6。
- **阴影** — 3 级，但**极克制**。暗色模式下几乎不用阴影，靠边框分层；亮色用 1–2px 的近距离软影。这是"白天鹅"的关键之一。
- **动效曲线** — 4 条 cubic-bezier 别让组件各写各的。`enter` / `exit` / `swift` / `gentle`，加 3 档时长（120 / 200 / 320ms）。

## 三、暗/亮、i18n、响应式——三件事的回答

**暗/亮**：**必须一开始就做**。事后加是地狱。做法是所有颜色 token 都写两份（`[data-theme="light"]` 和 `[data-theme="dark"]`），组件里**永远只用 `var(--color-x)`**，不写死颜色。我倾向**默认暗色**——VEW 是看视频的，暗色更"让媒体说话"。

**i18n**：现在搭。结构很轻：一个 `i18n/zh.json` + `i18n/en.json` + 一个 `t('key')` 函数 + `<html lang>` 切换。所有组件内文案不写死，全部 key 化。这一步成本极低，但漏了之后翻译就是噩梦。

**响应式**：和组件**部分相关，部分独立**。
- 组件层面：单个组件要响应式（按钮的 padding、卡片的字号、播放器控制栏布局），这是组件内部的事。
- 布局层面：断点系统（我倾向三档：`< 720` 移动 / `720–1200` 平板 / `> 1200` 桌面）。
- VEW 这种重浏览的产品，**桌面是主战场**，移动是次要——所以我会以桌面为基准设计，再向下适配，而不是 mobile-first。这个你认可的话告诉我。

## 四、视频卡——你最关心的，单独说

你说得对：一张图配标题就敢叫视频卡是耍流氓。我打算做这几种变体，**所有变体共享同一套交互语言**（hover 出操作、长按选择、右键菜单、键盘可达），区别只在密度和场景：

1. **`VideoCard.Grid` — 16:9 主力卡**（浏览页默认）
   缩略图 + 时长角标 + 标题（最多 2 行）+ 创作者 + 一行 meta（来源平台 icon + 时间 + 时长）。hover 时**缩略图微微放大 + 浮出快捷操作（喜欢 / 加入合集 / 更多）**。不出现"打开链接"的大按钮——整张卡就是点开详情，"原网页"在更多菜单里。
2. **`VideoCard.Portrait` — 9:16 竖屏卡**（TikTok/Reels 类）
   宽高比颠倒，比例更紧凑，标题更短。同样的操作语言。
3. **`VideoCard.List` — 列表行**（合集内、搜索结果、批量管理）
   左缩略图小 + 右多行信息 + 末尾操作。最适合密集浏览和拖排序。
4. **`VideoCard.Cover` — 大封面**（详情页头图、推荐位）
   16:9 全宽，无标题在卡上，标题在卡下。用于"展示这一个"。
5. **`CollectionCard` — 合集卡**
   不是一张图，是**三张缩略图叠层**（最近三个视频），合集名 + 视频数。点击进合集。
6. **`CreatorCard` — 创作者卡**
   头像 + 名字 + 来自平台 + 视频数。极简，浏览创作者列表用。
7. **`DownloadCard.Row` — 下载行**
   小缩略图 + 标题 + **细进度条**（高 2px，不是粗黑条）+ 速度 + 暂停/取消。**进行中和已完成视觉差别很大**——已完成的下载就是普通视频卡了，不再有进度元素。
8. **`NotificationItem`** — 时间戳左小点（未读才显示）+ 一句话 + 可选操作链接。整组放在 Popover 里。

**关于"简明 vs 操作"的平衡**：我的规则是——
- **静止时只露 1 条信息密度**：标题 + 创作者 + 一行 meta。
- **hover/focus 时露 3 个高频操作**（喜欢、加合集、更多）。
- **更多菜单里放 5–8 个低频操作**（编辑标签、刷新源、访问原网页、复制链接、刷新缩略图、删除…）。
- **批量模式下整卡变成可选状态**，左上角出 checkbox，所有 hover 操作隐藏。

这是"水面上从容、水面下划水"的具体体现：用户看到的永远是 1 行 + 3 个图标，需要的时候 8 个操作都在。

## 五、播放器哲学

你说的我完全同意。我会做成这样：

- **控制栏默认是浮层**（不是固定底栏），鼠标 3 秒不动**淡出消失**。
- **进度条高 2px**，hover 时长到 4px。**未播放部分是 8% 不透明的白**，已播放部分是品牌强调色，**缓冲段是 16% 不透明的白**。**没有红色，没有黑底**。
- **悬停在进度条上出现缩略预览 + 时间**，预览图是一个小圆角矩形浮在指针上方，**带极轻的阴影**，不是傻大方块。
- 控制元素：左侧 播放/上一个/下一个/音量， 中间空，右侧 倍速/字幕/画中画/全屏。**全部 24px 图标，hover 出极轻的 8% 圆形背景**。
- **键盘全可达**：Space 播放暂停，←→ 跳秒，JKL 倍速，F 全屏，M 静音。
- **状态**：加载（中央一个细圈 spinner，不是大转盘）、错误（一句话 + 重试链接）、缓冲卡顿（进度条上方一个极小的"buffering"灰字）、首帧未到（黑屏但**有缩略图 backdrop 模糊**填充，不是纯黑）。

## 六、API 我看到的缺漏 / 疑问

整体结构挺完整，**但有几个对"私人策展"场景偏关键的没看到**：

1. **个人笔记 / 备注** — 策展人会想给视频写一段为什么收藏。`PATCH /videos/{id}` 里可能有个 `note` 字段，但 schema 没展开看不到。**建议显式有一个 `note` 字段**。
2. **片内书签 / 时间戳标注** — "这段 1:23 的转场绝了"。没看到。这是**收藏者最想要的功能之一**。
3. **观看历史 / 最近观看 / 继续观看** — 没看到 `/videos/recent` 或 history 端点。
4. **字幕** — 没看到字幕相关。即使是代理流，前端要能挂载 VTT/SRT 也需要有源。
5. **软删除 / 回收站** — `DELETE` 都是硬删。**误删一个珍藏视频是会哭的**。建议有 trash + restore。
6. **标签层级或标签组** — 标签多了之后没有组织手段。`tags/merge` 有了但没有 `parent_id` 或 `group`。
7. **合集封面** — `CollectionUpdate` 里有没有 `cover_video_id` 或 `cover_url` 不清楚。建议明确。
8. **多档评级** — 只有 `like` 的二元状态。策展人常想要 ★★★ 或颜色标。可选。
9. **搜索历史** — `/search/suggestions` 是字典型还是用户历史型？如果只是字典，建议加一个用户搜索历史。
10. **设置项不够** — `/settings` 看起来只有 proxy。**主题（暗/亮/跟随系统）、语言、默认排序、网格密度、自动播放、首次进入页**这些用户偏好应该在 `/users/me/preferences` 里——这部分 schema 没看到，确认下有没有。
11. **`/system/restart`、`/system/setup`** — 这些**鉴权和确认流程**得清楚，前端会需要二次确认 UI。
12. **`/events` SSE** — 太好了。**前端的下载进度、解析状态、通知推送全靠它**，前端架构里我会留出一个全局事件总线对接它。
